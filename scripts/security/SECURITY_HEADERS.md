# Browser security headers

`prepareSecurityRequest(request)` creates the SSR policy and sanitized forwarded request headers. The proxy must pass those headers into `NextResponse.next({request:{headers}})` before rendering, including on cookie-refresh paths. Apply `securityHeaders(request,response,context)` to the final response with the same context. Caller-provided nonce and CSP headers are replaced.

`NSSO_CSP_MODE=report-only` is the initial rollout mode; `enforce` selects the enforcing header after preview checks. Dreamsea stays report-only because it is a separate app outside the reviewed provider inventory. Do not claim this setting enforces CSP for that app. Reports are not sent to a public collector, avoiding accidental transmission of profile URLs or other private data.

Dynamic SSR receives a fresh random nonce and Next automatically applies it to framework scripts. Any HTML response using a nonce must remain `private, no-store`; public profiles vary by viewer and marketing consent. Static pages use hashes of their actual inline scripts and retain normal static caching. No root layout `headers()` call forces the whole app dynamic.

`npm run build` performs two builds with one stable build ID. The first extracts SHA-256 hashes from every static HTML script; the second embeds the per-route policy in the proxy. It refuses the artifact if second-pass HTML contains an unapproved inline script, or if ISR is enabled without a compatible policy adapter. Build output records the final manifest under `.next/security/static-csp-hashes.json`; the committed source placeholder is restored after compilation. Coordinate builds because this process temporarily fills that placeholder. Framework upgrades must pass this build check and an actual HTTP/browser smoke before deployment.

Script sources are the same origin plus explicit PayPal/Meta hosts; the map route adds explicit Google hosts. Script attributes and arbitrary inline scripts are blocked. Framer Motion, React style props, and third-party controls require inline style attributes, so style policy permits them. Google Maps documentation includes `unsafe-eval`; that exception is scoped to `/places/dubai`, and development also permits eval for React debugging. User-authored images/media may use arbitrary HTTPS URLs, so image/media sources permit HTTPS; scripts, frames, and connections do not receive that broad permission.

Three.js r134 and Vanta 0.5.24 are served from `public/vendor`, with original licenses and SHA-256 provenance in its manifest. Their versions were retained. Meta Pixel initializes from bundled code only after consent, avoiding inline script exceptions and stale nonce problems during client navigation. The PayPal SDK loader must pass the initial document's nonce through `nonce` and `data-csp-nonce` when one exists.

Preview validation covers actual Next static/dynamic HTML in report-only mode before enforcement. Browser fixtures enforce the policy while checking injection denial, original background library loading, QR generation, mocked Maps/PayPal/YouTube integration, consent gating, same-origin chat requests and OAuth navigation. Provider mocks do not prove live authorization, billable Maps rendering, checkout settlement, or Meta delivery. A local HTTP fixture leaves Chrome caching enabled and confirms `private,no-store` responses are fetched again after identity changes. Deployment/CDN behavior still requires an HTTP check of the deployed artifact.

Official references: [Next.js CSP](https://nextjs.org/docs/app/guides/content-security-policy), [Google Maps CSP](https://developers.google.com/maps/documentation/javascript/content-security-policy), [PayPal SDK CSP nonce](https://developer.paypal.com/sdk/js/configuration/#data-csp-nonce).
