# nsso security operations

Ramin Hoodeh owns production access, response and recovery. Ordinary users retain free premium and simple sign-in. Only administrator and RazinFlix management operations require a verified authenticator session. Permission checks use fresh server membership and verified Auth identity; removing a membership takes effect on the next operation. Each approved editor must enroll their own authenticator at `/dashboard/security`. Do not copy or enroll their secrets for them. Keep sign-in-email access and authenticator recovery under the account holder's control. A lost factor requires a separately verified owner-led recovery through Supabase Auth; never restore the former public role field.

`Sign out other sessions` revokes refresh sessions. Issued access tokens can remain valid until expiry; a logout is not an immediate JWT revocation promise. On suspected compromise remove privileged membership first, preserve restricted evidence, then use Auth's supported session/factor recovery. Credentials are not automatically revoked or migrated by this release.

## Required release gates

Use the pinned Node version and deterministic `npm ci`. Require audit, secret scan, lint, type checking, behavior tests, rendered browser fixtures, real local Auth/Data API/Storage authorization tests and the production build. The build verifies static inline CSP hashes in two passes while dynamic SSR receives fresh nonces; no script `unsafe-inline` is permitted. Google Maps alone requires provider-documented `unsafe-eval`. Never skip a failed gate or re-enable a dangerous fallback to make a check green.

Only reviewed forward migrations belong in the live ledger. The guarded bootstrap is for an empty isolated project, never production. Apply additive contracts, deploy compatible callers, verify, then restrict the obsolete direct-write contracts. Verify the actual deployed revision from `/api/health` against the expected Git commit and check the migration ledger; a push alone is not deployment. Roll back to a compatible safe application or ship a forward fix. Never restore broad account writes, anonymous privileged RPCs, public private fields or raw HTML rendering.

## Monitoring and response

The production smoke workflow checks public routes, live database security posture, enforced headers and release identity. A failure creates a failed GitHub Actions run visible to the repository owner through their existing notification preferences. Do not silently change notification recipients. Hourly aggregate runtime signals and request-limit counters are backend-only. The public health endpoint exposes availability and revision only. High denial volume or repeated validated operational failures makes the health check fail. Vercel request logs remain useful for response/error rates; review provider alert delivery and retention in the hosting account whenever its plan changes.

After promoting and verifying a release, set the repository variable `NSSO_PRODUCTION_REVISION` to that exact full Git commit SHA and dispatch the production-health workflow. Missing or mismatched revisions fail the check. Updating this variable is part of every promotion or rollback; a syntactically valid but unapproved deployment is not a healthy release. Accounting settlement errors retain the conservative reservation and emit the same aggregate budget-unavailable signal as reservation failures.

For an alert: identify the affected route/revision and safe request ID; check aggregate errors and permission audit; temporarily disable the affected privileged write or provider call while retaining public reading; preserve evidence privately; determine impacted identities/content; restore only to a verified checkpoint; add a regression fixture and repeat the gates. Assess any notification duty from the actual incident and applicable requirements. Never publish tokens, profile text, private links, raw model actions, payment snippets or precise location in incident tickets or logs.

Rate controls reserve atomic per-IP-HMAC and shared request counters before expensive work. Gemini additionally retains its independent durable estimated monetary allowance; request limits are not provider billing ceilings. Photo/media limits count requests and bound each response's bytes. Google browser Maps usage must also use provider-side HTTP-referrer/API restrictions and quotas; backend counters do not control a copied public Maps key. Review those provider settings separately without widening the dedicated Gemini key.

## Retention and privacy

Runtime counters contain HMACs, never raw IPs, and roll off after two days when the limiter runs. Hourly aggregate signals roll off after thirty days when new signals are recorded. Security permission audit and operation receipts are owner-restricted; preserve replay prevention while applying a separately documented retention change, never silently delete an idempotency receipt. Account deletion/export requests require verified ownership and a reviewed relationship/retention inventory; do not run old wipe/seed scripts or promise deletion from provider backups before their retention expires.

Profiles and chosen contact fields are public by design. Draft full product bodies are owner-only. PayPal's hosted checkout and delivery remain the seller/PayPal flow: a redirect is not nsso proof of payment or an entitlement. QR networking now asks before reciprocal connection and accepts an optional typed meeting place; it does not silently acquire or send precise GPS coordinates to a reverse geocoder. Each user owns their notes. Removing a saved connection removes their own membership/notes only; the other person's independently held record remains theirs.

Database daily physical backups and object bytes have different coverage. Follow `STORAGE_RECOVERY.md`; test both relational data and referenced bytes, original ownership and foreign-user denial. Keep backup keys separate from encrypted snapshots. Private migration copies of original payment snippets and the ad-hoc release snapshot are recovery evidence, not general analytics: owner review/removal target is thirty days after release, subject to an active incident hold. Never restore old credentials from a snapshot.

Dreamsea and Qadam infrastructure are outside this work. Personal apps have explicit permissions/limits; dormant Web3 and search helpers stay outside the active runtime. Content/licensing classification and legal retention decisions require actual source/owner evidence and are not established by an automated vulnerability check.
